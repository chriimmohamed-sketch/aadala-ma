# TESTING — خطة الاختبار (TEST PLAN)

**الهدف:** منع أي ادعاء بأن ميزة تعمل دون دليل قابل لإعادة التشغيل.

---

## 1. الطبقات

| الطبقة | الأداة | ما تثبته |
|---|---|---|
| وحدة | Vitest | منطق MIYAR، الآجال، الاسترجاع، الأمان، المستندات |
| قبول (Acceptance) | Vitest + مسبار 5 أسئلة | أن RAG يجيب من المصدر الصحيح |
| نوعي | `tsc --noEmit` | عدم وجود أخطاء أنواع |
| بناء | `next build` | توليد 180 صفحة قانونية + كل المسارات |
| دخاني حي | `fetch /api/ai` | سلوك الإنتاج الفعلي |

## 2. الأسئلة المرجعية (Acceptance)

| # | السؤال | التوقع |
|---|---|---|
| A1 | ما هي أنواع الطلاق في المغرب؟ | مراجع من `family-code` (لا الدستور) |
| A2 | كيف أرفع شكاية؟ | `procedurePath` غير فارغ، certainty=`low` |
| A3 | مدة الطعن بالاستئناف | يشمل `civil-procedure` المادة 134؛ لا تحذير إحالات كاذب |
| A4 | ما هي شروط صحة عقد الشغل؟ | `labor-code` ضمن المراجع |
| A5 | ما شهادة صحة عقد البيع؟ | لا اختلاق؛ certainty=`low` مع تنبيه صلة |

## 3. اختبارات الأمان
- `rate-limit.test.ts`: الحجب بعد الحد + `retryAfter`.
- `validate.test.ts`: تطبيع، رفض الأسئلة الطويلة، locale.
- فحص حقن الموجّه يدويًا (نص السؤال لا يغيّر التعليمات).

## 4. اختبارات البيانات القانونية
- `retrieval.test.ts`: تطبيع، مطابقة عقد، رفض نص غير ذي صلة، `suggestNearest`.
- `acceptance.test.ts`: مسبار تشخيصي للأسئلة الخمسة (يطبع المراجع والجودة).

## 5. معايير النجاح
1. `npm run typecheck` بلا مخرجات.
2. `npm test` كل الاختبارات ناجحة.
3. `npm run build` ناجح، وكل صفحة `/legal/[slug]` مُولَّدة.
4. الأسئلة A1–A5 تعيد النتائج المتوقعة في `TEST_RESULTS.md`.

## 6. ما لا تغطيه الخطة
- اختبار جهاز حقيقي/RTL بصري.
- اختبار حمل (Workers limits).
- دقة قانونية للمحتوى (تحتاج مختصًا).
- OCR (غير منفّذ).
